## Model Architectures

Both models take **7 ADC samples** as input and output a single reconstructed energy value. They are designed for FPGA deployment under strict resource constraints.

### MLP — 148 parameters

```
Input:  [7]
Linear(7  → 10)    + ReLU    →  80 params  (weights: 70, bias: 10)
Linear(10 → 6)     + ReLU    →  66 params  (weights: 60, bias:  6)
Linear(6  → 1)               →   7 params  (weights:  6, bias:  1)
                              ─────────────
Total:                          148 params (trainable)
```

### CNN — 147 parameters

```
Input:  [1, 7]   (1 channel, 7 time samples)
Conv1d(1 → 4, kernel=3, padding=1)  + ReLU  →  16 params  (weights: 12, bias: 4)
MaxPool1d(kernel=2)                          →  [4, 3]
Conv1d(4 → 8, kernel=3, padding=1)  + ReLU  →  104 params (weights: 96, bias: 8)
MaxPool1d(kernel=3)                          →  [8, 1]
Flatten()                                    →  [8]
Linear(8 → 16)                      + ReLU  →  144 params (weights: 128, bias: 16)
Linear(16 → 1)                               →  17 params  (weights: 16, bias:  1)
                                             ──────────────
Total:                                          147 params (trainable)
```

> **Note:** Layer sizes are tuned to match the parameter counts reported in the paper (148 and 147 respectively). Minor layer configuration differences from the paper are acceptable as long as the total parameter count and FPGA footprint are equivalent.

## Loss Function

Both models are trained with a **hybrid loss**:

```
L = 0.5 * MAE + 0.5 * RMSE
```

This balances sensitivity to large outliers (RMSE) with robustness to small errors (MAE), which is important for the wide dynamic range of TileCal signals (from MIP-level to high-energy jets).

---

## Data Generation

Synthetic pile-up samples are generated by superimposing scaled TileCal reference pulse shapes across multiple bunch crossings, mimicking HL-LHC conditions (average μ ≈ 200).

> **Memory note:** The parameter `n_bunch_crossings` controls how many out-of-time pile-up contributions are included per sample. Reduce this value if memory is limited — the default reproduces the paper conditions but requires ~4 GB RAM for the full training set.
